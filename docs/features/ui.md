# UI

All the UI uses UI Toolkit; no UGUI canvas is left. `UI/UI.prefab` holds the HUD, inventory, results and pause UIDocuments and the EventSystem; the main menu and the pre-menu splash have their own. `ChangeUI` gives access to them (`GameScene.UI`) and opens the menus from the input; `IsMenuOpen` tells whether a menu covers the game (pause, inventory, results), and the menus raise `ChangeUI.MenuChanged` (`NotifyMenuChanged`) when they open or close. `GameFlow` loads the scenes behind a wipe (`SceneTransition`), and the options change the [edition](editions.md) behind the same wipe (`SceneTransition.Play(whileCovered, onDone)`).

The menus outside the game:

- `SplashScreen` (`0-PreMenu`, `Menus/Splash`) fades the studio logo in, holds it and fades it out while the main menu loads in the background; any button skips to the fade out, and the menu opens once it ends.
- `MainMenu` (`1-Menu`) switches between its home, options, credits and disclaimer screens (the `open` class on one of them). The disclaimer shows on the first launch, until closed: its `PlayerPrefs` key `DisclaimerSeen` then stays at 1. `Back` closes the disclaimer, or goes back home.
- In the game, `Back` goes through `ChangeUI.OnBack`, ignored while the player is dead or the results are shown, to `UIPause.ChangeStateOptions`: it closes the inventory if open, else leaves the options for the pause menu, else toggles the pause.

## Assets

UI Toolkit assets live in `Assets/UI`:

- `PanelSettings` (1920x1080 reference, expand mode) with the `Theme.tss` theme, importing `Styles/Common.uss` (tokens, panels, buttons, sliders, screens), `Menus.uss`, `Hud.uss` and `Inventory.uss`.
- The screens in `Menus`: `PauseMenu`, `Results`, `MainMenu`, `Inventory`, `Splash`. The pause and main menus share the `Options` template, bound by `OptionsView`. The options are the language (a change fades the options back in from 0.2 over `--duration-fade`, `.options--relocalizing`; not in the Classic) and the edition (a button per edition, `Editions`), the video (luminosity, shown as the image's brightness in percent, 2 to the exposure, and contrast, signed percent, every value written as the selected language writes percents, "100 %" in French, `OptionsView.FormatValue`; fullscreen and vertical sync on/off buttons, `GameSettings.IsSwitch`; without the sync, `Application.targetFrameRate` caps the frames at the screen's refresh rate), the audio volumes (master, music, effects, ambience, interface) and the low health's sound effects (a switch the Classic's sheet hides, `setting--anniversary`, as the effects it has not) and the gameplay settings (screen shake strength), saved by `GameSettings` (written to disk when the options close) and applied at each scene start by `SettingsLoader` (`Managers/SETTINGS.prefab`, which holds the color adjustments volume and the volume game parameters). The display mode is the exception: applied once per launch, then read from the screen, so that the mode Alt+Enter chose stays from one scene to the next and is saved for the next launch. They are split in pages, one shown at a time under a row of tabs (`options-tab`, `options__page` in the same order: gameplay with the language and the edition, video, audio; `OptionsView.ShowPage`, the first page on opening), the footer's reset button resetting the shown page after a second click (a `SecondClick`, dropped when the page changes or the options close; at once in the Classic, `confirmations` off); each setting holds its name on the left and its control on the right, a slider followed by its value (`setting__value`, added by `OptionsView`: percents, signed offsets). The options panel is wider than the pause one: the pause panel takes the `side-panel--wide` class while its options are shown and widens to uncover them. The pause menu shows a title above its buttons: Resume, Options, New run (`GameFlow.StartRun`; hidden in the Classic, whose pause didn't have it), Main menu and Quit. Its New run, Main menu and Quit buttons ask for a second click within the button's `--confirm-duration` (3 s on `.menu-button`; `MenuConfirm`, `SecondClick` of `MenuScreen.cs`, which swaps the `key` of a button implementing `ILocalizedText` and adds the `confirm` class); the results' Restart and Main menu buttons ask for one too (`--confirm-duration` 3 s on `.outline-button`), so that a reflex double click doesn't skip them. The pause menu sets `GameTime.Paused`, freezing the actions, the enemy turns and the animations behind it; `GameFlow` resets the time when it loads a scene. Leaving the game opens it (`ChangeUI.PauseFromOutside`): the window losing the focus in a build (Alt+Tab; the game runs in the background) and the Steam overlay opening (`GameOverlayActivated_t`), unless the results are shown or the player is dead.
- `Styles/Classic.uss`, `ClassicHud.uss`, `ClassicMenus.uss` and `ClassicInventory.uss`, not in the theme: `ClassicStyles` adds them to the screens' roots set up by `MenuScreen` while the Classic is shown, loaded then (Addressables) and released in the Anniversary with their textures; the Classic [edition](editions.md)'s look, under the `classic` class of the documents' roots (`Classic.uss`: tokens and shared rules; the others: each area's; button states, rectangles instead of cut shapes, the original's sprites and layout, no animation the original didn't have, the elements it didn't show hidden); a layout change of a screen may need its Classic rule updated too. A new animated or decorated element gets its Classic rule there.
- The filters in `Filters`, referenced by `GameAssets`: the `SlantedBlur` backdrop filter, the `ArtifactPiece` filter animating the inventory pieces by rarity and the `HealthBar` filter animating the health bars.

## Design tokens

The `:root` block of `Styles/Common.uss` holds every shared value of the UI as a USS custom property; the other style sheets declare no `:root` of their own. Write `var(--token)` rather than a literal whenever a token matches, and add a token (in its group, with a short comment) for a value that repeats or has a meaning; a value used once for a layout (a position, a panel size, a cut size) stays literal.

| Fonts | `--font-display`, `--font-body`; sizes `--font-size-xs` (14), `-sm` (16), `-md` (18), `-base` (22), `-lg` (24), `-xl` (28), `-2xl` (36), `-3xl` (52), and off the scale, for given texts: `-tag` (15, the cost tags), `-stat` (17, the health bar's and the enemy info's figures), `-popup` (26), `-popup-lg` (30, the armor popup), `-cooldown` (32), `-title` (40), `-menu` (42, the main menu's buttons), `-banner` (44), `-headline` (64, the results' message), `-display` (88, the pause title). The Anniversary's sheets write no duration in seconds but 0 and the menu background's slow pan |

Code reads a UI color from a custom property rather than hard-coding it: `CutShape` reads `--fill-color`, `--line-color`, `--shadow-color` (and the sizes `--cut-size`, `--line-width`, `--backdrop-blur`, `--shadow-offset`) and `ArtifactPiece` its outline's `--piece-line-color` (`CustomStyleResolvedEvent`, `customStyle.TryGetValue`); the feedbacks in the world take the UI's shield and heal colors from the HUD (`Hud.TryGetColor`, `--world-shield-color` and `--world-heal-color` of `.hud`: the `:root` tokens themselves are not in an element's `customStyle`). Sizes and durations too: a time is read as text by `UssTime` (`TryGetSeconds`, `Milliseconds`: "0.25s", "250ms" or a duration token), for `SlantedWipe`'s `--wipe-duration`, `ArtifactPiece`'s quarter turn and rarity flash (`--turn-duration`, `--flash-duration`), the action button's pulse, beat and second press (`--pulse-duration`, `--beat-interval`, `--confirm-duration`, `Hud`, `SecondClick`), the tooltips' delay (`--tooltip-delay`), the stagger of the menu lists' buttons (`--stagger-delay`, `MenuScreen`) and the ticks of a moving slider (`--tick-interval` on `.setting-slider`); no UI duration is a C# constant; the tooltips' sizes are numbers (`--tooltip-details-size`, and the Classic's `--tooltip-title-size`, `--tooltip-stat-size`, `--tooltip-stat-line-height`). Custom properties are read on the element whose rule sets them: `customStyle` doesn't see the inherited ones. The rarity colors are not tokens: they come from `RarityPalette`, shared with the relics (see [inventory](inventory.md#pieces)). The wipe of the HUD (`Hud.Fade`) and of `SceneTransition` takes its look from the `slanted-wipe` class.

## Layout

`Letterbox` computes the 16:9 area (`Viewport`) and fits every document in it (`Fit`); `CameraResolution`, on the game camera, sets the camera's rect to that area when the screen size changes. The HUD and the inventory share three columns: 600 points on the sides, 420 in the middle, 48 from the edges. A screen is shown by adding the `open` class. The `stretch` class of `Common.uss` fills the parent (absolute, 0 on every side): give it to an element rather than repeating the block in its own class.

Every screen script calls `MenuScreen.Setup(root, soundEmitter, sounds, originalSounds)` (`originalSounds` false for the HUD and the results, whose buttons the original didn't sound: they then sound only with the [edition](editions.md)'s `extraUISounds`, as the sliders' ticks), which fits it in the 16:9 area, sets the `classic` class on its root while the Classic [edition](editions.md) is shown, plays the button sounds of the `UISounds` asset (a moving slider ticks with the hover sound, every 0.08 s at most), staggers the buttons of its `menu-list` and uppercases the `caps` texts (USS has no text-transform), the rich text tags left as they are. A focus moved by the keyboard or the gamepad (`NavigationMoveEvent`) plays the hover sound, not one given by the code or a click. The pause menu, its options and the main menu's screens focus their first button shown as they open (`MenuScreen.FocusFirst`, once the screen's fade makes it visible), so that the arrows and Enter work at once; the results focus theirs only on the first navigation move (`FocusFirstOnNavigation`): Space, which ends the turns, is also the UI's submit key, and a reflex press must not restart the run.

## Components

Build the UI from the components of `Scripts/UI/Components` (`[UxmlElement]`, usable in UXML):

- `SlantedPanel`, `SlantedButton` and `SlantedLabel` draw the game's shape through `CutShape` (its polygons through the `PainterPaths` extensions of `Painter2D`, shared with `SlantedWipe` and `ArtifactPiece`): a rectangle with corners cut at 45°, up to parallelograms and diamonds, drawn under its text and children with a backdrop blur that leaves the cut corners sharp (`--backdrop-blur` 20 at most: the margins of `Filters/SlantedBlur.asset`, 20 points around the element for the horizontal pass, above and below only for the vertical one, the smallest that keep the same image). A `SlantedButton` has the `slanted-button` class: display font, accent colors while hovered, pressed in; `outline-button`, `hud-action` and `hud-bag` only add their size and differences. The HUD's two buttons (`Action`, `Bag`) are not focusable: clicked, they would keep the focus and Space (also the UI's Submit) would press them on top of ending the turn. Attributes `corners` and `dots` (the top line breaks in dashes next to a dot); size, colors, blur and sharp shadow from USS custom properties: `--cut-size`, `--fill-color`, `--line-color`, `--line-width`, `--backdrop-blur`, `--shadow-offset`. An element without text (`SlantedPanel`) draws the shape in its own mesh (`generateVisualContent`), redrawn as it resizes without allocating (the health bars' transitions); a text element (`SlantedButton`, `SlantedLabel`) draws its text before the generated content, so its shape is a `VectorImage` set as its background, recreated on each change of size or style.
- `SlantedWipe`, the screen transition: five horizontal bands cut at 45° sweep in from the left one after the other (a comb, not one diagonal) until they cover the element, then sweep out on the right. Drawn with the painter (`generateVisualContent`), no blur. `Cover(unscaledTime)` and `Reveal(unscaledTime)` are coroutines ending on the exact covered and hidden states, in game time or unscaled time, each frame counting 1/30 s at most so that the long frame loading a room or a scene doesn't skip half the sweep; it blocks the pointer while shown and is not displayed once revealed. Look from USS custom properties, set by the `slanted-wipe` class of `Common.uss`: `--fill-color` (`--color-fade`), `--wipe-duration` (a time, `--duration-wipe`), and `--wipe-plain` (1: one rectangle fading in and out linearly, the Classic's room fade); `Instant` covers and reveals at once (`SceneTransition`'s scene loads without the profile's `sceneWipe`). `Hud.Fade` (the room changes, in the 16:9 area, game time) and `SceneTransition` (the scene loads and the edition changes, whole screen, unscaled time) use it. While a `SceneTransition` keeps the screen covered (a scene loading, an edition changing), a diamond turns in the bottom right corner once the cover lasts `--loading-delay` (0.5 s, `.loading-diamond` of `Common.uss`); a cut (the Classic's scene loads) shows none.
- `MenuButton`, `LocalizedLabel` (the `key` attribute reads the UI string table), `HealthBar` (health, armor, the trail of the health lost, its text "current (armor) / max" with the armor written only while there is some, unless the element's `--zero-armor` is 1 (`ClassicHud.uss`: the original's "100 (0) / 100"), its text also in three labels hidden unless a style places them, `health-bar__split` with `health-bar__current`, `__slash` and `__max`, as the Classic's, `Preview(healthLost)` blinking the health an action would take at the end of the fill; the `health-bar` filter, `UI/Filters/HealthBar.shader`, `.mat` and `.asset` referenced by `GameAssets.healthBarEffect`, animates lightly its health, a vertical gradient, a faint current and a sheen every 4.5 s, and its armor, drifting diagonal stripes, a top highlight and a sheen every 2.8 s, set about 30 times a second with the mode, the part's size and the time, while the bar is shown (not the boss bar outside a boss fight); a `--ui-effects` of 0 set on the element itself by `ClassicHud.uss`, leaves the filter out, as for `ArtifactPiece`'s), `EnergyGauge`, `CostTag`, `SkillSlot`.
- `RefuseShake.Play(element, class)`, not an element: shakes an element sideways to refuse an action, holding the class (its refusal colors) while it shakes; the skills and the energy gauge use it.
- `HudTooltip`, a `SlantedLabel` shared by the elements registered on it (`Register(element, text provider, placement, delay)`): hovering one shows its text after the registration's delay provider (milliseconds, read at each hover; 0 at once) or the tooltip's `--tooltip-delay` (0.4 s, `Hud.uss`); leaving it, removing it from the panel (a rebuilt list) or blocking the tooltip hides it. The provider returns null for no tooltip, and builds its text with the tooltip's `Format(title, body, details)` (bold title, details at `--tooltip-details-size` percent) and `Wrap(text, tag, property, unit)` (a rich text tag set to a size property of the tooltip, how `TimelinePanel` sizes the original's infobox) and `HudTooltip.StatusLine(stats)` (the status effects with their turns, also used by `EntityInfoPanel`), and the owner calls `Refresh` from its events (stats, energy) to rewrite the shown text. `StatColor` is the color of a text's secondary lines, the `--tooltip-stat-color` set on the tooltip itself, or its text color. `Tint(text, color)` colors a stat of the text with one of the tooltip's stat colors (`HealthColor`, `ArmorColor`, `EnergyColor`, `MovementColor`: `--tooltip-health-color`, `--tooltip-armor-color`, `--tooltip-energy-color` and `--tooltip-movement-color`, set on `tooltip--anchored` from the stats' design tokens), or leaves it as it is if the tooltip has none. An element hovered inside another registered one (the armor inside the health bar) takes over and gives the tooltip back when left. `Placement.Styled` leaves the tooltip where its USS puts it, `Placement.Above` centers it above the element, below it if there is no room, kept 16 points inside the HUD. The HUD has three: `Tooltip` (skills), `StatusTooltip` (`tooltip--status`) and `HoverTooltip` (`tooltip--anchored`: the stats and the timeline); `Hud` blocks them while a menu is open (`ChangeUI.MenuChanged`). A new tooltip registers on one of them (or a new `HudTooltip` in the UXML with the `tooltip` class) rather than handling the pointer itself.
- `RichText.Highlight(element, text)`, not an element: colors the damage and block tags of a localized text (`<D>`, `<B>`) with the `--highlight-color` set on the element showing it (the skills' `.tooltip` and the inventory's `.artifact-info__box-text`, `--color-accent`), or removes them if it has none.
- `ElementVisibility.IsShown(element)`, not an element: whether an element is drawn (on a panel, visible, neither it nor an ancestor out of the layout). The animations scheduled on an element (`ArtifactPiece`, `HealthBar`) pause while it returns false: the scheduler keeps running on hidden elements.
- `ArtifactPiece`, built by code only (not a UXML element): an artifact's piece in the inventory, generated from its shape, rarity and icon (see [inventory pieces](inventory.md#pieces)). Its geometry (the inset outline, the cells cutting the icon, the icon's place) is `ArtifactPieceLayout`, static, shared with the piece preview of the artifact's inspector.

A text element with children (a button with dots or a bar) is not sized by its text, in width nor height: `MenuButton` puts its text in a child label for that reason, and a `SlantedButton` or `SlantedLabel` with dots needs a set width and height.

## Style rules

- Blur only what is behind a panel, with the backdrop filter; never blur the whole screen (no depth of field).
- Keep the cut shapes at 45°, and make the hovers change colors only: a state selector (`:hover`, `:active`, `:focus`) never sets a margin, padding or size, or the hovered element moves its neighbours.
- Use the [design tokens](#design-tokens) rather than literal colors, font sizes and durations.
